# 性能试验：按需斥候与状态驱动回报

本文件是 0.33 的**试验配置**，不是降低 Gate、独立验收、需求覆盖或 Hook 边界的理由。只有同宿主 A/B 结果证明质量不降、返工不增后，才可把其中的具体预算变成默认行为。

## 按需斥候

| 情况 | 流程 |
|---|---|
| 路径、接口和影响范围已知且信息未过期 | 主力做最小确认 → 实现 → 搜剿 |
| 路径已知但影响范围不确定 | 微型斥候：只查关键依赖与行号 → 主力 |
| 路径未知、Registry 过期、文档与现状冲突 | 受限斥候 → 主力 → 搜剿 |

斥候只交：路径清单、文件:行号的可疑点、约束、建议最小范围、是否 blocked。默认不贴代码、不复述设计全文；正常回报不超过 15 行或约 1.5KB。主力收到斥候结论后，不重复大范围探索。

## 回报与读取

- M1 在需求对齐、派工、异常/风险、收口时输出；普通进展只传新的状态或决定。
- 成功回报建议为：状态、变更摘要、证据路径、验收命令与结果、未决项。
- 小型终端输出可贴聊天；大型输出须完整归档为项目证据，聊天仅给路径、摘要和必要片段。
- 大件（默认超过 100 行或 4KB）优先按章节、行号区间或检索结果读取；阈值是宿主可调默认，不是跨宿主铁规则。

## A/B 判定

在同一宿主、同一项目基线、同类任务中比较现行流程（A）与本试验流程（B）。最严格方式是从同一 Git 基线建立两个独立工作目录并执行同一需求。

B 必须同时满足：原 Gate / 独立验收 / 范围检查和用户最终体验均通过；同根因返工、需求重复解释、越界和状态错乱不增加。记录：总 step、M1/工人回报长度、大件整读次数、用户手动传话次数与上下文压力。一次只证明可用；建议至少三组同类任务稳定后再固化规则。
